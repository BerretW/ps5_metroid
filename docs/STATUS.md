# Acceptance status

Statuses are evidence-based: **PASS**, **FAIL**, or **NOT TESTED**. Update after running validation; a source implementation alone does not count as a runtime result.

**Milestone: PLAYABLE prototype.** The native Windows application builds and launches, the shared gameplay simulation passes its headless tests, and the PS5 controller build is reported playable by the operator. This is a development baseline, not a claim that every feature or platform behavior is complete.

## Echo Framework verification

Latest statically validated controller package: `dist/ps5-controller/PPSA91007`, `eboot.bin` **1,611,105 bytes**, SHA256 `c2f4c1407f16f2accf02f0924607bc4d10fcf6476a94a55e642a186bd874b153`. The external `assets/framework/game.json` is 758 bytes, SHA256 `19ad794a0b85b6e3047349d739873672a385d01f359122a110613e8671ab64b4`; the dialogue remains revision 3 (SHA256 `ce40dbc8b1345ba19ded40a76dc497b237e931f175e5d1f4c0633f1155fd981e`). Transfer the complete title directory to include the configuration and dialogue. The seven system runtime imports and bundled clean-room libc hash are unchanged; keyboard/IME imports remain absent. yyjson 0.13.0 is linked statically, with its MIT notice packaged. Hardware execution of this revision is NOT TESTED.

Evidence: `build/windows/.build-logs/` (latest Release build/test), `build/ps5/logs/controller-release/commands.log`, `game-build.stdout.log`, `game-readelf.stdout.log`, and `PPSA91007-validation.json`; compiler commands and retained response files are under `build/ps5/game-controller/`. `tests/ps5_package_tests.ps1 -Controller` exercises the controller package, including negative validation cases and the absence of keyboard/IME imports.

The existing fixed-step game loop and gameplay objects remain authoritative. Framework integration handles configuration/module startup, game-state reset/resume, Mira's JSON dialogue and the Echo Step action/condition/event projection. Dialogue conditions read projections of the authoritative inventory and ability state. The SDL app wires both platform storage providers into the versioned gameplay checkpoint flow. The provider diagnostic passed on PS5, and the operator reports the gameplay autosave works on an earlier console build (2026-11-21).

The component schema API, deterministic manifest exporter, resource-manifest validator, and schema-driven CLI editor are verified on Windows. The generic editor retains only the built-in Transform2D; opt-in PROJECT ECHO editor/export executables additionally register the project's dialogue interaction descriptor. No PS5 hardware result is claimed for the latest integration.

`EchoFramework::Narrative` is an optional reusable static library with a headless example, focused tests, and a bounded loader for one dialogue JSON document at a time. PROJECT ECHO requires and links it for Mira's interaction. The game supports optional Czech speaker, line and choice fields with English fallback, a bounded UTF-8 bitmap glyph set, and persisted EN/CS selection.

The foundation is usable but broader framework acceptance remains incomplete: a reusable platform-neutral application coordinator, finer compiled module selection, hardware verification of keyboard rebinding, and future migration of additional gameplay objects remain outstanding. Save codec tests use in-memory storage, and the Windows provider test uses disposable Local AppData storage. See [framework roadmap](framework/ROADMAP.md).
