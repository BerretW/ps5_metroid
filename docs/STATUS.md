# Acceptance status

Statuses are evidence-based: **PASS**, **FAIL**, or **NOT TESTED**. Update after running validation; a source implementation alone does not count as a runtime result.

**Milestone: PLAYABLE prototype.** The native Windows application builds and launches, the shared gameplay simulation passes its headless tests, and the PS5 controller build is reported playable by the operator. This is a development baseline, not a claim that every feature or platform behavior is complete.

## Echo Framework verification

Verified 2026-11-20. Latest statically validated controller package: `dist/ps5-controller/PPSA91007`, `eboot.bin` **1,506,993 bytes**, SHA256 `abbd8c78f0123cd39ac27ab88c8928018f7aea5a2bb22666fbb6c4533ece987e`. Its 15 assets include the required `assets/framework/game.json`. The seven system runtime imports and bundled clean-room libc hash are unchanged; keyboard/IME imports remain absent. yyjson 0.13.0 is linked statically, with its MIT notice packaged. This package was rebuilt after the Windows storage provider was added; the new provider is excluded from PS5 builds. The exact current package has not been run on PS5 hardware; the operator-confirmed run was an earlier framework-linked build.

Evidence: `build/windows/.build-logs/` (latest Release build/test), `build/ps5/logs/controller-release/commands.log`, `game-build.stdout.log`, `game-readelf.stdout.log`, and `PPSA91007-validation.json`; compiler commands and retained response files are under `build/ps5/game-controller/`. `tests/ps5_package_tests.ps1` also passes against the separately built standard package, which must not be deployed because its known-crashing keyboard path remains enabled.

The existing fixed-step game loop and gameplay objects remain authoritative. Framework integration only handles configuration/module startup, new-game state reset, the Echo Step action/condition/event projection, and shutdown. The operator confirms an earlier framework-linked controller build starts and the game runs on PS5; this is an operator-reported hardware result, not a run performed by the build host. The JSON condition decoder has Windows test coverage, but PROJECT ECHO does not yet consume it at runtime. Windows storage is tested separately; the PS5 provider passes cross-compilation and static validation, but its first console probe failed directory initialization. Neither provider is wired to gameplay.

The foundation is usable but the full broader framework acceptance is not complete: a reusable platform-neutral application coordinator, finer compiled module selection, the PS5 hardware storage test, and migration of the gameplay state/object graph to persistent saves remain outstanding. Save codec tests use in-memory storage, and the Windows provider test uses disposable Local AppData storage; neither proves PS5 persistence or restores the game's object graph. See [framework roadmap](framework/ROADMAP.md).

The opt-in PS5 storage diagnostic is built with `scripts\build-ps5.ps1 -Target Game -StartupDiagnostics -SkipPs5Keyboard -SaveStorageDiagnostics`. Its distinct package is `dist/ps5-save-diagnostic/PPSA91007`. The first diagnostic (`bdb48597...`) failed parent-directory initialization in the operator's 2026-11-21 log. The second (`1f96b6b5...`) reported `lstat_errno=1` with a working `open+fstat` fallback, passed write, replacement and read-back, and failed enumeration with `opendir failed errno=1`. The third (`596eb13c...`) replaced `opendir` with a 4 KiB `getdents`, which failed with `errno=22`. The fourth diagnostic tries ordered 64 KiB raw-directory variants (no-follow `getdents`, `getdirentries`, `sceKernelGetdents`, `sceKernelGetdirentries`, then plain-open `getdents`/`sceKernelGetdents` with an `fstat` directory check), and logs the chosen method or every attempt's errno. Its `eboot.bin` SHA256 is `865de685076ce98ec1b1af5f3763733d50386de612ebcf92ed8c4f3546e9c044` (1,527,841 bytes). Static package validation, PS5 package tests and Windows Release 8/8 tests passed; on 2026-11-21 the operator reported the fourth package's console run as `PS5 save storage probe: PASS` with `enumerate: method=getdents64k`. Build logs, compiler/linker commands, ELF inspection, and package validation are under `build/ps5/logs/save-storage-diagnostic/`. After success the probe leaves the reserved `framework_probe.sav` under `/data/project_echo/saves`; its expected result is `PS5 save storage probe: PASS` in `/data/project_echo/logs/project_echo.log`.
